Weissman Check — Technical Spec

Markdown (devpost/spec.md) is canonical; this page is a visual companion and works offline.

How it works

Browser app (React + TypeScript): everything you see, plus the instant explaining work: text check, entropy verdict, replay of the first ~8 KB, and the formulas.

Python server (FastAPI): runs the six real compressors at fast and strong settings, times each (median within a time budget), keeps compressed bytes in memory for downloads, streams each finished run, and computes all the maths once: the static, dynamic and browser-best winners and 9 Weissman tables (3 units × 3 baselines). The browser only switches which precomputed value is shown.

Nothing is saved. No accounts, no database.

Weissman W = (r/r̄) · (ln T̄ / ln T), zstd(fast) vs gzip-6 (210,000 B, 0.030 s):

Same data, different verdict. In seconds both times are under 1 s, so the score is flagged: faster compressors score lower. Exactly 1 unit, or mixed signs, shows undefined. Never NaN.

Replay Card ReplayCard.tsx, lib/lz77.ts

First 8 KB only (labelled). Greedy match finder, 3-byte hash, 4 KB window, min match 4. Counter adds length − 3 per match. Stop/Restart affect only the animation. PRD: Replay card.

Analysis (single source of truth) backend/app/analysis.py

Sent with the done event. Assumed network 20 Mbit/s. Static/dynamic rule above. If the winner is lz4/xz/bzip2, banner also names the best of gzip/brotli/zstd. PRD: Results: recommendation banner.

Weissman and "break it" analysis.py + WeissmanControl.tsx

Units s / ms / µs × baselines gzip 6 (default), gzip 1, zstd 3 = 9 precomputed tables. Edge cases: T ≤ 0, ln T = 0, ln T̄ = 0, opposite signs → undefined; both logs negative → flagged; each with a one-line note. PRD: Results: Weissman "break it" control.
