Scope said
"See the results… a recommendation that accounts for static versus dynamic."
Now we know
A one-line banner comes first, with a static/dynamic toggle on it. Flipping it can change the winner on screen. Below it sit a per-row results table and a Weissman "break it" control.

The journey

Pick a step below. The highlighted box shows where you are.

1 · Hero

  • A looping animation of a block of text squeezing into a smaller block.
  • App name and a Start button. Nothing else.

2 · Compressor page, before a file

Narrator box — guided tour (Next / Skip tour)
Left: dropbox + 3 sample buttons
JSON API response · server log · minified JS
Right: carousel (6 cards, include checkboxes) + narration card
Replay card (square): narrator's intro text
Metrics box: metric names greyed out, each with a "?"

Empty state: drag-and-drop text and samples. A refresh always returns here.

3 · Drop a file

  • The text appears as a plain preview in the replay card, with nothing highlighted yet.
  • A file chip shows name, size and an entropy verdict ("Highly repetitive, worth compressing" / "Already dense, little to gain") with a "?" tooltip.
  • Not accepted: binary or image ("handles text-like files for now…"), over 25 MB (limit stated), empty ("nothing to squeeze").

4 · Choose what to compare

  • Six carousel cards, each in its own colour, each with an include checkbox. All are checked by default.
  • Reading a card changes the narration card under it. It doesn't change what's included.
  • gzip, brotli, zstd and lz4 explain how they use repeats. xz and bzip2 explain their different approach in words only.
  • No compressor checked: Run is disabled, with "Pick at least one compressor."

5 · Run

  • The dropbox area becomes a 12-segment progress bar. Each segment fills in its compressor's colour when that run finishes.
  • The replay starts alongside it: a cursor sweeps the text, repeats light up with labels ("repeat of 14 chars from 120 back"), and a "bytes saved so far" counter climbs.
  • The metrics box on the right shows live values and fills in as each segment finishes. After the run, the results table on the left replaces it.
  • One compressor fails: its row says "failed" and the others continue.

6 · Results appear

Banner: "Ship brotli (strong) for static assets: 78% smaller, decompresses at 410 MB/s" at assumed 4G [static ⇄ dynamic]
Best = shortest time to a user. Static: transfer + decompress. Dynamic: compress + transfer + decompress.
If the winner is lz4/xz/bzip2: "Fastest to deliver overall: xz (strong). Best for browsers: brotli (strong)."
Table: compressor × fast/strong · browser-supported mark · size · % saved · compress speed · decompress speed · Weissman (gzip level 6 baseline) · download
Weissman "break it": change the time unit or baseline and watch the ranking change

Results take over the left half automatically. The replay card becomes a tall rectangle and keeps going (Stop / Restart).

7 · Act

  • Flip static/dynamic on the banner.
  • Download any row's real compressed file.
  • Change the Weissman unit or baseline.
  • Try another file brings the dropbox back and keeps compressor selections.

Is it done? Checkable criteria

Narrator and tour
  • First arrival shows step 1 with Next and Skip tour.
  • Skip tour dismisses it and the app stays fully usable.
File input
  • Dropped or sample text files show a preview and a file chip with name, size and entropy verdict.
  • Binary, oversize and empty files show their friendly message and don't run.
Benchmark and progress bar
  • Run benchmarks every included compressor at both settings on the real file.
  • 12 segments fill as runs finish; unchecked ones show as skipped.
Replay card
  • Labelled "How LZ-style compressors see your file (simplified replay)".
  • Highlights come from the user's actual file, with length and distance labels.
  • Stop and Restart affect only the replay.
Banner, table and Weissman control
  • The banner is the first result and names compressor, setting, % saved, decompress speed and the assumed network speed.
  • The toggle changes the banner on screen, because compression time counts only in dynamic mode.
  • If the winner isn't browser-supported, the banner shows the overall winner and the best browser one.
  • The table marks browser-supported compressors (gzip, brotli, zstd).
  • Each table row downloads a real compressed file; failed rows say "failed".
  • The Weissman control changes the scores and ranking on screen.

Boundary

Building now
  • Hero + compressor page
  • Dropbox, 3 samples, preview
  • Carousel, include checkboxes, narration cards
  • Real benchmark, 6 compressors × 2 settings, segmented progress bar
  • Replay card
  • Banner, table, Weissman "break it", Try another file
Deferred
  • Separate libraries and metrics pages (content lives in narration cards and tooltips)
  • Avatar animation
  • Per-compressor custom visualizations
  • Images and video
  • Non-developer audience; deployment
Non-goals
  • Solo mode
  • Show branding
  • Claiming live compressor internals
  • Accounts, saved history, stored uploads

Look and feel

2013–2015 flat design: bright white and light grey, flat 1px-bordered cards, one blue accent, one colour per compressor used everywhere, a humanist sans with a monospace for numbers and file text, and a single moment of flair in the progress bar.
